# E0064 — Lone Monk: original-camera semantic framing before denoiser study

**Preinscribed 2026-11-16.** Central goal: demonstrate an actual residual fidelity error of Blender native OIDN for render-architecture details before suggesting any new ACD algorithm. E0062 accepted author Carlo Bergonzini / Monorender's official Blender Cycles Lone Monk (CC BY, full 33,452,252-byte source SHA256 eea2bbfb3f9271050f523c8351fca40f2f559ce84b42b0143e949ecdb4594c3b). E0063 verified two noticeably different low-spp Raw inputs on original scene daylight/cam.001 (relative RMSE 0.372), **but neither 96×54 nor seed variation alone proves fidelity**.

## Decision for immediate work

The only original scene camera has not been inspected at useful resolution. Picking a tiny high-density ROI blindly would risk scoring a flat region, a background prop, or cherry-picking denoiser failures retrospectively. Render exactly **one original-camera full-frame 960-pixel-wide 8-spp Cycles preview** for selecting *physically recognizable architectural edges/materials*, plus measured CPU time. Preserve source camera/lens, original aspect ratio and pixel aspect; calculate height using full-file saved render ratio, do not squish into an assumed 16:9 frame. No source file save. Disable compositor/denoise and do not read filtered output. An alteration to an exposure node can change display look, so this is framing only, not a photometric reference.

Predeclared input and execution: Blender 5.2.4 CPU, seed539, samples8/adaptiveOFF, scene daylight/cam.001, original SHA/byte length checked before render; output PNG RGB with CC BY attribution, machine metadata original size/frame/color, output SHA, luminance 1/50/99% and render wall seconds. Require exact source metadata and rendered pixel size; reject missing textures, scene/camera mismatch, nonfinite/empty preview. This is a small-budget prerequisite, **not** a 960px denoising benchmark and not a new filter.

## Scientific next gate (not authorized solely by preview)

After inspecting the actual image, preregister up to two distinct physically meaningful architectural features (e.g. stone joints/cornices/arch edges only where actually visible) in the exact full-frame normalized camera coordinate system, a 512×512 render border at virtual 1920px density and a margin for OIDN tile context. For each selected physical detail, first verify reference disagreement with at least two separate sample sequences, same noisy Raw and guides, and cost. Report scene-linear HDR errors, reference uncertainty, masked gradient error **against a held-out independent reference**, flat-region noise regression, and render-time trade-off vs higher spp. Do NOT infer errors from border gain alone (E0059), do not tune mask after seeing OIDN outputs, do not present this development source as blind holdout.

**Stop rule:** if no meaningful architectural detail is visible in this camera, record that and reject it as the *detail fixture* (though source functional audit remains valid). If source is too costly to reference, switch to another truly independently authored licensed scene. No High/Super, sharpen, SID5 quality claims, new model, fork, or stable addon changes. Keep PR#10 draft. Preview does not establish improvement or converged ground truth.
