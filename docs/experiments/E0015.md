# E0015 — Comparación aislada OIDN CLI 2.3.3 vs 2.5.1, mismos PFM y flags

Fecha 2026-11-12. [Run #43234478588](https://github.com/mxlzz/ACD/actions/runs/43234478588): **success, dos jobs reales**. Nuevo comparador `scripts/oidn_versions_compare.py`, con binarios oficiales descargados sin modificar, CPU, flags `-d cpu --hdr color.pfm --alb albedo.pfm --nrm normal.pfm -q high`, exactamente los mismos PFM por semilla para ambas versiones. El binario 2.5.1 se verificó contra SHA256 del asset GitHub Releases `743c3e2aff8c220d5d70fe6cb970fb3d36f2702d2693c61d1d148e404cf37cd6`. Binario 2.3.3: SHA registrados en artifacts pero Release API no declara digest, por lo que falta anclar externamente ese checksum. E0014 cubre la comparación del CLI con el nodo nativo.

## Datos y alcance

Dos escenas procedurales **192×144**, 24 spp ×3 semillas (539, 1337, 911), dos referencias 1024 spp (8819, 8922), Blender5.0.1 CPU. En cada fila se comparan outputs sobre la **primera** referencia; ambas versiones usan exactamente mismos beauty/albedo/normal de cada seed. El script verifica reproducción determinista v2.5.1: diferencia máxima = 0 para todas las semillas.

## Inferencia limitada

- **Glass:** ambas versiones resultaron numéricamente idénticas en estos tres seeds. Esto indica que la actualización no cambia las salidas del filtro usado bajo esta entrada/configuración. No implica que las bibliotecas sean iguales ni que todo input sea invariante.
- **Interior emisivo:** 2.3.3 produce un RMSE global ligeramente menor en 3/3 seeds (diferencia absoluta 0.00004–0.00012). El cambio de versión introduce salida diferente (RMSE mutuo ~0.00221–0.00225), pero casi no cambia el error de bordes. No atribuir a una mejora o degradación general.
- El nodo de Blender y ambos CLI difieren en política de prefiltrado/guías; E0015 **aísla mejor el cambio de versión que E0014**, pero no prueba que un addon basado en 2.5.1 se comporte exactamente igual que Blender.
- La máscara de bordes deriva de referencia finita y su métrica no está validada perceptualmente. Ni muestras independientes ni convergencia están probadas; no afirmar ventaja de SID5 comercial.

## Próxima puerta

Diseñar escena explícitamente orientada a detalles reales de alta frecuencia (slats, juntas, vidrio con fondo estructurado, microbump), más allá de 192×144. Comprobar si las métricas de gradiente detectan blur vs detalle sin favorecer sharpening; después validar en escena pública real o profesional licenciada. Evitar repetir Glass/interior indefinidamente. Comparadores de OIDN standalone se mantienen disponibles, pero benchmarking costoso solo cuando aporte una variable nueva.


### Actualización metodológica posterior — E0016

[Corrida #43235485653](https://github.com/mxlzz/ACD/actions/runs/43235485653) comparó de nuevo CLI 2.3.3 y 2.5.1. En interior emisivo esta vez ambas salidas fueron **idénticas** por seed (RMSE mutuo 0), aunque en E0015 diferían ~0.0022. Al comparar artifacts, los **binarios tienen idénticos SHA entre runs**, pero los inputs PFM difieren levemente (para seed539, RMSE color entre runs `4.96e-5`). OIDN2.5 output varía más entre runs que OIDN2.3. Hay una **posible dependencia de ISA/arquitectura CPU**, ya que OIDN v2.4 introdujo AMX-FP16 y v2.5 optimizó ese camino, pero **todavía no fue medida la ISA en esos jobs**. Por ello se rebaja la afirmación de que 2.3.3 es mejor en interior a un **resultado local de una ejecución**, sin reproducibilidad cruzada demostrada. Ver [E0016](E0016.md) y diagnóstico ISA por programar.
