## Escena de alto detalle

`tests/scene_detail_target.py`, Blender5.0.1 CPU, **320×240**, 52 lamas verticales con juntas/materiales alternados, malla de juntas (26 filas, 13 columnas), barra metálica glossy, vidrio delante de algunas lamas, panel de bump procedural. Entrada 24 spp × semillas 539/911/1337, referencias 1024 spp × 8819/8922. Caso sintético construido para tener frecuencias espaciales difíciles; **no equivale a un render profesional a 1080p**.

Dos referencias difieren en RMSE lineal **0.04609371**; discrepancia 0.2077003 veces el RMSE crudo/referencia (debajo de la alerta exploratoria 0.25). Test heurístico de diversidad de tres entradas **aprobó** (RMSE pares 0.3067–0.3108), pero independencia Monte Carlo y convergencia de referencia **no demostradas**.

## Hallazgo de reproducibilidad entre ejecuciones E0015 y E0016

Comparamos **los artifacts reales** `E0015-interior` y `E0016-interior`. Los hashes del binario `oidnDenoise` **no cambiaron**:
- OIDN 2.3.3 bin SHA256 `84eb33133f22284a9448e8d7e91d84cda30be30a2840bec61ca72a33bc567341`
- OIDN 2.5.1 bin SHA256 `1cb3a28ebc99b90d7548b0b8b16f70c163cb59abe8582458a254aa303338269c`
- Pero los PFM **no fueron idénticos entre jobs** pese a semillas/render nominal idénticos: para seed 539, color RGB `RMSE=4.96e-5`, max abs 0.01191; albedo RMSE 1.01e-9; normal exactamente idéntico. Esto impide tratar las corridas como mismo input entre runs.
- Entre ejecuciones, salida v2.3.3 cambió RMSE `7.47e-6`; salida v2.5.1 cambió RMSE `0.0022133` en seed 539. Sin embargo v2.5.1 fue determinista al repetir **mismo PFM en el mismo runner**, y E0016 interior produce salidas idénticas v2.3.3/v2.5.1 para las tres seeds, mientras E0015 mostraba diferencias de ~0.0022. **E0015 no demuestra ventaja intrínseca estable de v2.3.3**.
- Tiempos CLI seed 539 (no benchmark comparable entre máquinas): E0015 v2.3.3 ~44.3 ms, v2.5.1 ~4.35 ms; E0016 v2.3.3 ~42.7 ms, v2.5.1 ~19.35 ms. La dependencia de arquitectura CPU/ISA es una explicación plausible, **todavía no verificada**. Según [changelog de OIDN v2.4/v2.5](https://github.com/RenderKit/oidn/blob/v2.5.1/CHANGELOG.md), se añadió y aceleró AMX-FP16 en CPUs y `devices/cpu/cpu_device.cpp` reporta explícitamente ISA bajo modo verbose.

## Consecuencia

1. Para inferir diferencia por versión es obligatorio registrar **modelo CPU, ISA efectiva, backend, flags y hashes** además de los inputs. La prueba CLI entre versiones se controla dentro de una misma máquina, pero no equivale a independencia de arquitectura. Un experimento específico de ISA con **PFM sintético idéntico por SHA entre runners** debe aclarar los resultados antes de atribuir causalidad.
2. Queda un avance medible en laboratorio de detalle, **ninguna mejora algorítmica demostrada**. F5 no se habilita por este experimento. Se necesita un caso real 1080p+ con texturas auténticas, AOVs y referencias de calidad (o un dataset público equivalente) para evaluar si la experiencia visual de SID sobre detalles responde a un error observable de OIDN.
